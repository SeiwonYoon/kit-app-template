## 문제/증상 (정리)

1. **타임라인 재생 중 포트상태가 통째로 비어 보임**: `-`로 바뀌었다가 다시 채워지는 듯한 깜빡임.
2. **막대그래프 깜빡임**: 전체 위젯 재생성/빠른 갱신으로 시각적으로 번쩍임.
3. **막대가 갑자기 몇 배 빠르게 채워짐(버스트)**: UI 드레인 지연으로 큰 dt가 한 번에 누적.
4. **배속에서 막대가 실제 시간 증가보다 느리게 채워짐**: wall-clock 기반 스무딩 상한이 배속을 반영하지 않음.
5. **포트 헤더의 `t=`가 사라졌다가 다시 나타남**: `sim_time=""` 호출에서 헤더를 `t=` 없는 텍스트로 덮어씀.

---

## 원인 분석

- **포트상태 비움/깜빡임**
  - UI 갱신 경로가 여러 개(이벤트/프로그레스/레이아웃 재조립)이고, 일부 payload가 `ports_occupancy`를 누락/빈 dict/부분 dict로 전달하면 UI가 “전부 EMPTY” 또는 `-`로 덮어쓸 수 있음.
  - 분할 레이아웃 재조립(`_rebuild_sim_monitor_split_ui`) 시 port cell이 기본값(`EP1:-`)으로 잠깐 다시 만들어질 수 있음.

- **막대 점프(버스트)**
  - `sim_time` 업데이트가 UI 큐 지연으로 띄엄띄엄 도착하면 `dt = t_now - t_last`가 커져 세그먼트가 한 번에 누적되어 “순간 가속”처럼 보임.

- **배속에서 막대가 느림**
  - virtual time 스무딩에서 `dt_wall` 기반으로만 전진하면, 배속(예: 5x)에서 실제 `sim_time`은 5배 빠르게 전진하는데 막대는 1배 속도로만 따라가 느려 보임.

- **포트 헤더 t= 깜빡임**
  - 복원/재조립 직후 호출에서 `sim_time=""`로 헤더를 `t=` 없는 텍스트로 덮어써서 다음 정상 업데이트 때 다시 나타남.

---

## 최종 해결(현재까지 적용된 방향)

- **payload 계약 강화(스냅샷 유지)**
  - progress에도 `ports_occupancy` 포함(엔진 레벨).
  - UI는 `ports_occupancy`가 빈 dict/부분 dict/전부 빈 값이면 last snapshot으로 폴백/merge하고, 무의미한 값으로 last snapshot을 덮어쓰지 않도록 방어.
  - 레이아웃 재조립 시에도 last snapshot으로 즉시 복원.

- **EP 타임라인 스무딩**
  - 세그먼트 누적을 wall-clock 기반 virtual time으로 바꿔 “버스트 점프” 방지.
  - 배속을 반영(`dt_wall * speed`)해서 배속에서도 `t(sim)` 속도를 따라가도록 보정.

- **포트 헤더 t= 유지**
  - `sim_time`이 빈 호출에서는 헤더를 덮어쓰지 않도록 변경.
