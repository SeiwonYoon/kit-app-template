## 문제/증상 (정리)

1. **막대 vs t(sim)**: `timeline_only`가 `virtual_now`를 쓰면 SimPy 이벤트 사이에서도 막대 `dt`가 쌓여 진행 패널의 시뮼 시각보다 빨리 보일 수 있음(분할에서 두드러짐).
2. **단일 화면 깜빡임**: 매 갱신마다 `ep_timeline_widget` 전체 destroy/rebuild.
3. **분할 막대 잘림**: 고정 `BAR_W=420` + 이름·우측 라벨·패딩이 열 너비를 초과; 가로 스크롤 없음.
4. **이력이 전부 화면1**: `_format_history_line` → 이모지 접두 후 `^\[화면N]` 매칭 실패 → 폴백으로 화면1만 갱신.

---

## 원인 분석

- (1) UI 막대 축과 엔진 “표시용 시뮼 시각” 소스가 **`virtual_now` vs `env.now`**로 어긋남.
- (2) 동일 프레임·동일 데이터인데도 전체 위젯 트리 재구성.
- (3) `Fraction(1.0)` 열 폭 대비 행 최소 폭이 큼.
- (4) 라우팅이 **포맷 후 문자열** 기준이라 접두가 더 이상 줄의 시작이 아님.

## 최종 해결

- 엔진: `timeline_only`의 `sim_time` = **`env.now`** (주석으로 의도 명시).

- 이력: **raw strip → `[화면N]` 분리 → body만 포맷 → `_append_sim_log_channel(si, …)`**.

## 추가 (같은 날): FOUP 공정 prim 위치 유지(옵션 A) + 보호 4종

### 문제
- FOUP_PROCESS_START 시 EP 포트 LOT prim 을 `+Y 320` 만큼 이동시켜 두면, 다음 시퀀스(예: 다른 lot 의 ARRIVED/MOVE 등)가 시작될 때 `restore_port_lot_prims_to_authoring()` 가 모든 매핑 prim 을 authoring 자세로 복원해 버려서 **+320 오프셋이 사라지고 prim 이 원위치로 되돌아간다**.

### 해결(옵션 A: FOUP 진행중 prim 은 baseline 복원에서 제외)
- **`port_lot_visibility.py`**
  - `_FOUP_IN_PROGRESS_PATHS: Set[str]` 추가.
  - `mark_foup_in_progress(path, on)`, `clear_foup_in_progress()`, `is_foup_in_progress(path)` 추가.
  - `restore_port_lot_prims_to_authoring()` 안에서 `path in _FOUP_IN_PROGRESS_PATHS` 면 `continue`(translate/rotate stop 도 건너뜀).
  - `clear_port_lot_authoring_cache()` 안에서 `_FOUP_IN_PROGRESS_PATHS.clear()` 도 같이 수행 → reset 시 자동 정리.
- **`control_window.py`**
  - `handle_sim_event_for_animation` 의 FOUP 분기:
    - `FOUP_PROCESS_START` → `mark_foup_in_progress(prim_path, True)` 즉시 등록.
    - `FOUP_PROCESS_END` → `_schedule_foup_inprogress_unmark(ext, prim_path, delay_sec=1.05)` 로 `-Y 320` 복귀 애니가 끝난 시점(약 1초 뒤)에 해제.
    - 1회성 update event subscription 으로 deadline 도달 시 `mark(False)` + self-unsubscribe. 객체는 `ext._foup_unmark_subs` 에 보관.
  - `on_sim_stop_clicked` 안전망: `clear_foup_in_progress()` + 보류된 unmark subscription 모두 해제.
  - `on_sim_start_clicked` 안전망: 시작 직전 `clear_foup_in_progress()` 한 번 더.

### 부작용 검토(요약)
- (A) 동일 FOUP prim 을 다른 시퀀스가 직접 움직이는 케이스 → 현재 sim_sequences 에 없음(검증 완료).
- (B) END 의 `-Y 320` 진행 중 다른 시퀀스가 들어와도 1초 지연 unmark 로 prim 보호.
- (C) Reset 시 잔여 플래그 → `clear_port_lot_authoring_cache()` 가 함께 정리.
- (D) START 만 발생하고 END 가 누락되는 비정상 흐름 → Reset/Stop 양쪽에서 강제 클리어, Start 진입부에서도 한 번 더 클리어.
- (E) 멀티 컨텍스트(분할화면) → 기존 restore 가 기본 컨텍스트만 처리하던 한계는 별개 사안. 옵션 A 의 set 은 path 기준이라 모든 컨텍스트에 일관 적용됨.

### 관련 함수에 단계별 한글 주석 추가
- `handle_sim_event_for_animation` 전체 흐름을 `0/1/2-A~K` 번호로 블록 주석 정리(동작 변경 없음).

  공정이 끝나면 `CASE_03`,
  회수(REMOVED) 후 포트상태가 초기화되는 시점에는 `phong1` 로 변경한다.

### 적용 타이밍(요청대로 “후보 2” 채택)

  `has_lot=False` 가지 — 즉 LOT prim 을 `MakeInvisible()` 하는 그 자리에서 같은 호흡으로 material 도 `phong1` 로 되돌림.

### 경로 변경 위치(한 곳에서만 수정)
`source/extensions/morph.tbs_control_1/morph/tbs_control_1/port_lot_visibility.py` 상단 상수에서 변경.
```python
MATERIAL_PATH_FOUP_PROCESSING = "/Root/World/Looks/CASE_02"
MATERIAL_PATH_FOUP_DONE       = "/Root/World/Looks/CASE_03"
MATERIAL_PATH_FOUP_DEFAULT    = "/Root/World/Looks/phong1"
```

### 신설/변경 함수
- `port_lot_visibility.py`
  - 상수: `MATERIAL_PATH_FOUP_PROCESSING / DONE / DEFAULT`
  - `bind_material_to_prim(stage, prim_path, material_path)` — 단일 prim material 바인딩(예외는 삼킴).
  - `apply_port_lot_prim_material_for_context(usd_context_name, prim_path, material_path)` — 화면별 컨텍스트 안전 호출.
  - `restore_port_lot_prims_to_default_material(usd_context_name)` — Stop/Reset 안전망 일괄 복원.
  - `apply_port_lot_prim_visibility_for_context(...)` — `has_lot=False` 가지에서 `MATERIAL_PATH_FOUP_DEFAULT` 로 자동 바인딩.
- `control_window.py`
  - `handle_sim_event_for_animation` 의 FOUP 분기에 1-D-2 단계로 material 바인딩 호출 추가
    (START → `MATERIAL_PATH_FOUP_PROCESSING`, END → `MATERIAL_PATH_FOUP_DONE`).
  - `on_sim_stop_clicked` 안전망에 `restore_port_lot_prims_to_default_material(None)` + 보조 컨텍스트(`_sim_multi_context_names`) 일괄 복원 추가. Reset 은 Stop 을 먼저 호출하므로 자동 커버.

### 분할화면 처리
- FOUP 분기에서 `_usd_context_name_for_sim_screen(ext, scr)` 로 얻은 `ctx_nm` 을 그대로 헬퍼에 전달.
- Stop 안전망에서는 `ext._sim_multi_context_names` 를 순회하며 모든 보조 컨텍스트의 stage 도 함께 복원.

### 부작용/리스크 검토
- `port_lot_prim_paths.json` 의 path 가 mesh 가 아니라 Xform/그룹이면, material 바인딩이 자식들에게 상속되는 형태가 됨. 의도와 맞는지 prim 단위 확인 필요.
- material prim 이 stage 에 존재하지 않으면 `bind_material_to_prim` 이 조용히 False 반환 → 외형만 그대로 유지(에러 없음).
- 보호 set(`_FOUP_IN_PROGRESS_PATHS`)은 위치 보호 용이며 material 과 무관 → 이번 변경과 충돌 없음.
