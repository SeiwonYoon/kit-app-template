## 원인 분석

### 1) 완료 이벤트 콜백 내부에서 NameError 가능

- `play_usd_animation()`의 완료 이벤트 핸들러 `_on_complete()`에서
  `global _complete_sub`, `global _end_fix_sub`를 참조하는 코드가 있었는데,
  파일 전역에는 해당 변수가 정의되어 있지 않음.
- 완료 시점에 해당 코드가 실행되면 `NameError`가 발생할 수 있고,
  `_on_complete()`는 전체가 `try/except Exception: pass`로 감싸져 있어 예외가 조용히 삼켜지면서
  아래쪽 `on_completed()` 호출까지 도달하지 못하는 케이스가 발생 가능.

### 2) `play_usd_animation()` 실패 시 `_done()` 미호출

- `play_usd_animation()`는 내부 예외에서 `False`를 반환할 수 있음.
- `sequence_engine.py`의 `USD_TIMELINE` 스텝은 반환값을 확인하지 않고 `return`하기 때문에,
  `False`가 발생하는 순간 해당 스텝의 완료 콜백(`_done`)이 호출되지 않아 시퀀스가 멈출 수 있음.

## 추가 이슈: 시뮬 종료 후에도 EP 막대그래프가 계속 진행됨

## 작업 목표

- 시뮬레이션이 자연 종료(완료)되는 시점에 EP 막대그래프 진행도도 즉시 종료되도록 처리
- 요약 로그의 “총 공정시간”과 막대그래프의 총 시간(스케일)이 반드시 일치하도록 보장

---

## 문제/증상

- 시뮬레이션 완료 로그가 출력된 이후에도,
  - 포트상태 아래 EP 막대그래프가 계속 전진하거나
  - 막대그래프 상 “총 시간(전체 길이)”보다 더 진행되는 현상이 발생
- 요약 로그에는 총 공정시간이 명확히 표시되지 않거나,
  표시되더라도 막대그래프 총 시간과 일치하지 않음

---

## 원인 분석

- UI는 “이벤트 대기” 구간에도 그래프가 진행되게 하기 위해
  `control_window.py`에서 **UI 스레드 wall time 기반 가상 sim_time ticker**(`_sim_ep_timeline_ui_sub`)를 사용함.
- 이 ticker는 Stop/Reset에서는 unsubscribe되지만, **자연 종료(완료) 경로에서는 자동으로 꺼지지 않아**
  시뮬 종료 후에도 가상 시간이 계속 증가 → 막대그래프가 계속 진행될 수 있음.
- 또한 막대그래프의 총 시간(스케일)은 `sim_total_est_sec`(예상치) 기반으로 고정되는 구조가 있어,
  완료 시점의 실제 `env.now`(요약 로그 `전체 t`)와 불일치가 발생할 수 있음.

---

## 최종 해결

- 시뮬 완료 감지 시점(완료 시 enqueue되는 `EXPORT_XLSX` 액션 처리)에서:
  - `_sim_ep_timeline_ui_sub`를 unsubscribe하여 **종료 후 그래프 전진을 중단**
  - 각 화면별 최종 `env.now`를 읽어
    - 막대그래프 스케일(`total_est_fixed`, `sim_total_est_sec`)을 **최종 시간으로 확정**
    - 즉시 1회 재렌더하여 “종료 시점에서 멈춘 화면”을 보장
- 요약 로그(`simulation_engine.py`)에 `총 공정시간` 라인을 추가해,
  “요약 로그의 총 시간”과 “막대그래프 총 시간”이 같은 기준(최종 `env.now`)임을 명확히 함

## 추가 이슈: EP 개수=3 변경이 실행 중 반영되지 않음(멀티 화면)

## 문제/증상

- EP 개수 콤보를 `3`으로 두면 최초에는 포트 상태(EP3/BP4 칸)가 정상 표시되지만,
  시뮬레이션 진행 후 콤보를 변경하면 포트 상태 패널에 반영되지 않음.

---

## 원인 분석

- 포트 상태 패널의 EP3/BP4 표시 여부는 콤보값이 아니라 화면별 스냅샷(`_sim_per_screen_snapshots[*].ep_count_idx`)을 우선 사용한다.
- 시뮬 시작 시 `_auto_fill_per_screen_snapshots_on_start()`가 스냅샷을 자동으로 채우면서 ep_count가 사실상 고정되었고,
  이후 콤보만 변경하면 스냅샷 값이 그대로라 UI가 바뀌지 않는 것처럼 보였다.

---

## 최종 해결

- `on_sim_ep_count_changed()`에서 콤보 변경 시점에
  존재하는 화면별 스냅샷 dict들의 `ep_count_idx`를 현재 콤보 값으로 즉시 동기화하여,
  시뮬 진행 중에도 EP3/BP4 표시가 정상 반영되도록 수정.

## 추가 이슈: EP 타임라인 막대가 시뮬 시간보다 빠르게 진행(배속 이중 + 엔진/UI 중복 누적)

## 문제/증상

- 시뮬레이션 진행시간(엔진 기준)과 포트상태 아래 EP 타임라인 막대의 시간 전진이 다름
- 특히 시뮬 배속(`speed`)을 올리면 막대가 더 빨리 올라가는 느낌

## 원인 분석

- tick 스레드는 이미 `sim.tick(dt * speed)` 형태로 **배속을 엔진 시간 예산에 반영**한다.
- 동시에 EP 타임라인용 UI ticker(`_sim_ep_timeline_ui_sub`)가 `wall * speed`로 가상 시간을 누적하면,
  **배속이 두 번 곱해져** 막대가 엔진 `sim_time`보다 빨리 진행할 수 있다.
- 추가로, 엔진은 `timeline_only` progress로 **주기적으로 `sim_time`(virtual_now)을 이미 emit**하는데,
  UI ticker가 동일한 막대그래프 경로에 wall dt 누적을 더하면 **시간이 이중으로 전진**할 수 있다(배속과 별개로도 체감이 매우 큼).

## 최종 해결

- UI ticker는 `wall dt`만 누적하고, 배속은 tick 스레드의 `sim.tick(dt * speed)`에만 적용하도록 수정.
- UI ticker의 `dt`도 tick 루프와 동일하게 상한(0.1s)으로 클램프해, 프레임 지연 시 막대 시간이 과도하게 튀는 현상을 완화.
- 엔진이 `timeline_only`로 알려준 최신 `sim_time`을 화면별로 캐시(`_sim_ep_engine_sim_time_by_screen`)하고,
  UI ticker는 **엔진 sim_time보다 앞서지 않도록** vt를 재동기화한다(중복 누적 방지).
