### 1.5 H1 — Bake / Evaluator concurrency fix (저녁 추가)

#### 증상

X3 (in-memory bake) 적용 후 사용자 보고:
- `[Bake]` 가 끝나면 baked layer 안에 `composed attrs with timeSamples>0: 0` /
  `sdf_dict_timeSamples=0 static(default)=5063` — 즉 **모든 attribute 가 static
  pruning 되어 dynamic timeSamples 가 0 개**.
- `TIMESAMPLES_REPLAY` step 으로 재생해도 viewport 가 정지.
- `omni.timeline` 의 ▶ 재생도 막힘 (LayerOffset(0, 1e-9) freeze 가 매 tick 다시 author
  되어 reference 평가가 멈추므로).

#### 원인

`_on_update_option_e` 가 매 main update tick 마다:
- `_ensure_option_e_omnigraph_deactivated()` — instance sublayer 에
  `over { active = false }` author (TIMESAMPLES_REPLAY 모드 보장용).
- `_ensure_option_e_freeze()` — `LayerOffset(0, 1e-9)` author (reference timeSamples freeze).

bake (`bake_prim_to_timesamples_async`) 가 `await app.next_update_async()` 로 main
update tick 으로 양보하는 사이, 위 두 함수가 다시 호출되어:
- bake 시작 전에 잠깐 OmniGraph 를 활성화했던 것이 **scrub start 직전 다시 deactivate**
  → 모든 frame 의 `xformOp:translate` = (0,0,0) → static prune.
- LayerOffset freeze 가 매 tick 다시 author 되어 user 의 ▶ 재생도 정지.

#### 해결

`RuntimeEvaluator` 에 **bake-in-progress 표식** 도입 — `_master_timeline_prims` 와
동일 패턴.

| 신규 항목 | 역할 |
|---|---|
| `_bake_in_progress_prims: Set[str]` | bake 가 진행 중인 prim_path 표식. |
| `begin_bake_mode(prim_path)` | 표식 추가 + LayerOffset(0,1) 복귀 + OmniGraph sublayer `active=True` + freeze/deactivate seen reset. |
| `end_bake_mode(prim_path)` | 표식 제거 + freeze/deactivate seen reset → **다음 update tick 에서 자연 복귀** (TIMESAMPLES_REPLAY 모드). |

가드 추가:
- `_ensure_option_e_freeze`: `if prim in _bake_in_progress_prims: return`
- `_ensure_option_e_omnigraph_deactivated`: `if prim in _bake_in_progress_prims: return`

`lam_window._on_bake_instance._runner` 는 기존 `set_omnigraph_active_for_instance(True/False)`
대신 `begin_bake_mode` / `end_bake_mode` 호출. 모든 early-return 경로(예외/실패/attach
실패/hot-reload mismatch) 에 `_end_bake_mode_safe()` 호출.

scheduler 는 위임 메서드 `begin_bake_mode` / `end_bake_mode` 추가.

#### 검증

사용자 OK — `test1.usd` (OmniGraph 자산) 단일 인스턴스 `[Bake]` → `TIMESAMPLES_REPLAY`
재생 정상 동작 (xform animation viewport 반영). `composed attrs with timeSamples > 0`
도 양수로 회복.

멀티 인스턴스 시연(A1) 은 본 fix 의 회귀 위험이 없도록 prim_path 단위 set 으로
설계 — 한 인스턴스 bake 중 다른 인스턴스의 TIMESAMPLES_REPLAY 평가는 가드를 우회하지
않는다.

### 1.4 X3 — In-memory bake (디스크 *_baked.usd 제거)

사용자 요청 원문 (`source/prompt.txt:239-244`):

> 현재 _baked.usd 방식 유지는 없애줘
> 별도의 usd 를 생성하지 않았으면 좋겠어.
> 휘발성이라도 내부 메모리에 timeSamples 형식으로 변환된 데이터를 들고 사용하도록 하면 되,
> 어차피 이 경우는 테스트 용으로 사용할 것이라서 매번 usd 를 로드할 때마다 bake 과정을 거쳐서
> 메모리에 저장해도 상관없고 대신 bake하는 경우 로그에 변환된 timeSamples 데이터 형식을
> 확인할 수 있게끔만 되었으면 좋겠어.

이 요구는 직전에 보류했던 X2 (master.usd 안 박기) 와 다르다. **X3 = anonymous
`Sdf.Layer` (메모리 only)** 로 박는 방식이며, master.usd 는 일절 손대지 않는다.

#### 구현

1. `bake_prim_to_timesamples_async` 에 `output_mode: str = "memory"` 파라미터 추가.
   - `"memory"` (기본): `out_layer = Sdf.Layer.CreateAnonymous(...)` 까지는 기존과 동일.
     마지막 `out_layer.Export(...)` 만 생략하고 layer 자체를 `BakeResult.baked_layer`
     로 반환. layer identifier 는 `anon://__lam_bake__/<asset_basename>.usda`.
   - `"file"`: 기존 디스크 출력 동작 그대로 유지 (다른 도구가 import 할 때 사용 가능).
2. `BakeResult` 에 `baked_layer: Optional[Any]`, `output_mode: str` 필드 추가.
3. `AnimationInstanceRuntime.setup_offscreen_stage_from_layer(layer, asset_path=...)`
   신규 메서드 — `Usd.Stage.Open(layer)` 로 root 가 anonymous layer 인 stage 생성.
   기존 `setup_offscreen_stage(asset_path)` 와 동일 lifecycle, FPS 30 정규화 동일.
4. `RuntimeEvaluator.attach_memory_baked_layer(prim_path, baked_layer)` 신규 메서드 —
   해당 인스턴스 runtime 의 offscreen Stage 를 baked layer 로 교체 + attr_cache /
   diag flag 무효화. runtime 이 없으면 lazy create.
5. `lam_window._on_bake_instance` 흐름 변경:
   - 기존: bake → `*_baked.usd` 디스크 저장 → `forget_instance` → `remove_usd` →
     `add_usd(baked.usd)` → 새 runtime 생성.
   - 신규: bake (memory) → `attach_memory_baked_layer(prim_path, baked_layer)`.
     인스턴스 교체 없음. master.usd 의 reference 는 원본 자산 그대로 유지 (Option E
     의 LayerOffset freeze 가 master 의 평가를 막으므로 충돌 없음).
6. `_log_baked_layer_dump(layer, ...)` 헬퍼 함수 — bake 종료 시 baked layer 의 prim /
   attr / timeSamples 형식을 콘솔에 dump. 사용자 요구 "변환된 timeSamples 데이터 형식
   확인" 충족. 각 attr 마다 path / typeName / timeSamples 개수 / 처음 N 개 + 마지막
   1 개 (tc, value) / static pruned 표시. 너무 큰 경우 truncate.

#### 영향

- 디스크 *_baked.usd 파일이 더 이상 생성되지 않음. 기존 파일이 디스크에 남아있다면
  사용자가 직접 정리 필요 (LAM 코드는 자동 삭제하지 않음).
- master.usd 에 baked 자산이 over 로 박히지 않음 (X2 의 단점 회피).
- Kit 재시작 시 메모리 layer 가 소멸 → 다시 [Bake] 필요. 사용자 명시 OK.
- 인스턴스 교체 (remove_usd / add_usd) 사이클이 사라져 사용자 viewport 가 깜빡이지
  않고 즉시 baked 결과가 적용된다.

#### 옛 X2 보류 결정 무효화

직전 §1.4 의 "X2 보류" 결정은 X3 로 대체됨 — X3 는 X2 의 단점을 모두 회피한다 (master
비대화 X, multi-instance 충돌 X, 자산 전달 영향 0).

## 9. 2026-05-12 후반 핫픽스 — UI 상태/뱃지 (Q1, Q2)

### 9.1 Q1 — bake 완료가 UI 에 안 보이는 회귀

**증상**: 사용자가 [Bake] 를 눌러 in-memory baked layer 가 attach 되어도 UI 의 인스턴스 행은
계속 `OMNIGRAPH (bake 필수)` 로 표시됨. 사용자가 bake 완료 여부를 알 수 없음.

**원인**: `inst.asset_kind` 는 자산 자체 분류 결과(파일을 스캔한 정적 정보) 라 bake 후에도
변하지 않음. bake 완료를 표현할 별도 상태 필드가 없었다.

**조치**:

- `lam_types.AnimationInstance` 에 `baked: bool = False` 필드 추가. in-memory baked layer
  attach 성공 시 True 가 박힌다.
- `lam_runtime_evaluator.attach_memory_baked_layer` 성공 마지막 단계에서 `_instance` 를
  찾아 `baked=True` 마킹.
- `lam_window._refresh_instances` 가 `inst.baked` 를 보고 라벨에 `· BAKED ✓` 뱃지를
  덧붙이고 색상을 초록으로 덮어쓰며, [Bake] 버튼 라벨을 `Re-bake` 로 전환.
- `_on_bake_instance._runner` 의 attach 성공 직후 `self._refresh_instances()` 호출 →
  사용자가 별도로 list 열고 닫지 않아도 즉시 라벨/버튼이 갱신된다.
- Kit 재시작 시 in-memory baked 는 휘발되므로 다음 세션은 자동으로 `baked=False` 로
  시작 (D13 정책 그대로). 사용자가 "다시 USD 를 로드하면 원래대로 되어도 된다"고 합의한 동작.

### 9.2 Q2 — 새 USD 추가 시 UI 가 `UNKNOWN` 으로 먼저 그려지는 회귀 (분류 동기화 순서)

**증상**:
- 첫 번째 USD 추가 → UI 에 `UNKNOWN` 으로 표시.
- 두 번째 USD 추가 → 첫 번째 행은 `OMNIGRAPH (bake 필수)` 로 갱신, 두 번째 행은 `UNKNOWN`.
- 즉 *항상 가장 마지막에 추가된 행*만 UNKNOWN.

**원인 (Listener 동기화 순서 버그)**:

```
MultiUsdLoader.add_usd()
  └─ self._registry.register(...)             # 안에서 self._notify() 동기 호출
        └─ listener: lam_window._refresh_instances()   # ← 이 시점 inst.asset_kind = UNKNOWN
  └─ inst.asset_kind = asset_kind             # ← 박힘은 register() 가 return 한 *후*
```

`_refresh_instances` 가 인스턴스 생성 즉시 동기 호출되는데, `asset_kind` 는 아직 박히지
않은 상태였다. 다음 add_usd 호출에서 listener 가 다시 트리거되면 이전 인스턴스는 이미
박혀 있어 정상 라벨, 새 인스턴스는 또 같은 이유로 UNKNOWN — 한 칸씩 밀리는 증상이 나옴.

**조치 (정합 fix)**:

- `AnimationInstanceRegistry.register` 시그니처에
  `asset_kind: Optional[str] = None`, `asset_diag: Optional[Any] = None` 추가. 인스턴스
  생성 직후 `_notify` 호출 *전*에 두 값을 박는다.
- `MultiUsdLoader.add_usd` 가 register 호출 시 `asset_kind` / `asset_diag` 를 인수로 전달.
  register 가 박은 뒤 listener 가 호출되므로 UI 는 처음부터 올바른 라벨로 그려진다.
- `MultiUsdLoader._register_only` 도 동일하게 register 의 새 인수를 사용 — 폴백 경로
  (context 없음 / pxr 없음 / stage None / author 예외) 에서도 UNKNOWN 회귀 없음.
- `composition_discovery` 등 다른 register 호출자는 새 인수에 기본값 `None` 이라 영향 없음.

**핵심 원칙**: "listener 가 보는 첫 상태가 최종 상태와 같아야 한다." Registry 가 만든
객체의 분류 / 메타데이터는 `register()` 안에서 박혀야 하며, 호출자가 `register()` 가
return 한 뒤 박는 패턴은 listener 동기 호출로 인한 race 를 만든다.
